# Open items

This is the hub's one list of open SSSF work. Each design keeps its reasons and decisions; the to-do lives here, with a link back. None of these blocks a run.

To add an item, add a row in its place in the sort and link the doc that explains it. When an item closes, delete its row: the commit says what closed it, and the design doc records the outcome where it matters. Items about an unlisted project are kept in the private list, never here.

Each SSSF item has a type, a priority, a severity and a status, the fields most issue trackers use. The rows are sorted by type, then priority, then severity.

| Field | Means | Values |
|---|---|---|
| Type | what kind of work it is | **Bug**: something SSSF or agentsh does wrong today, including a gap in what the guard promises. **Feature**: something new SSSF can't do yet. **Enhancement**: a check, a hardening step, or tidying of what already works |
| Priority | the order to work in, weighing severity against cost and what it unblocks | **P1**: work on next. **P2**: before agentsh reaches more projects. **P3**: when its area is next touched. **P4**: only when something calls for it |
| Severity | how bad it is if left alone | **Critical**: an agent did harm, or got past the guard, in a real run; stop runs until it's fixed. **High**: a gap in what the guard promises, or a blocker for the next rollout step. **Medium**: a real defect that fails closed, costs time or disk, or is likely to bite soon. **Low**: fails closed and rare, cosmetic, or waiting on evidence |
| Status | what it waits on | **Ready**: the work is known and nothing blocks it. **Needs info**: it waits on evidence from a real run. **Deferred**: it waits until a repo needs it. **Needs decision**: it waits on the engineer |

How these map onto common trackers:

| Here | GitHub | Jira |
|---|---|---|
| Type | a `type:` label: bug, feature, enhancement | Issue type: Bug, New Feature or Story, Improvement |
| Priority | a `priority:` label, P1 to P4 | Priority: Highest to Lowest |
| Severity | a `severity:` label | a Severity field, where a project adds one |
| Status | `status:` labels, such as needs-info or blocked; open or closed | Status: To Do, In Progress, Done; with a label or flag for blocked |

Severity and priority differ: severity is the harm, priority the order. A high-severity item can wait behind a cheaper one that unblocks it. Severity was first set on 2026-11-12 and priority the same day. Set all four on each new row, and change them when what the row could do, or what it waits on, changes.
